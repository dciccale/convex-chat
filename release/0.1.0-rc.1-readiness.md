# 0.1.0-rc.1 readiness report

Assessment date: 2026-08-08

Status: **candidate implementation ready for CI compatibility confirmation; not
published**.

## Evidence completed

- Convex Components marketplace approval.
- Maintainer-validated web and real-mobile-device flows against a Convex
  development-cloud deployment.
- Frozen `0.1` package and behavior contract, including reply deletion semantics,
  modeled-but-unsupported schema state, stable errors, and resource limits.
- Component authorization coverage for read/write, read-only, none, inactive,
  non-member, history-boundary, author, and cross-scope cases.
- Adversarial coverage for external-key and message idempotency conflicts,
  concurrent creation and sends, sequence allocation, read monotonicity,
  reactions, and pagination while new messages arrive.
- Critical component coverage gates of 85% statements/lines/functions and 75%
  branches. The initial hardened suite exceeds every threshold.
- Clean tarball installation, public declaration/export snapshot, host-wrapper
  typecheck, optional test-registrar import, and production dependency audit.
- Upgrade, staged schema migration, rollback, security-review, and release
  procedures.

## Findings fixed during hardening

1. External conversation-key retries now reject a changed kind, title, or member
   set instead of silently returning an incompatible conversation.
2. Message retries now include the reply target in their idempotency contract.
3. Recommended host wrappers now expose bounded conversation and message
   pagination arguments.
4. Public transaction-shaping identifiers and attachment metadata are bounded.
5. Package test peers, cold-build resolution, tarball contents, and exports are
   verified without relying on workspace aliases or Turbo cache.

## Remaining gate

- The committed CI compatibility matrix must pass on Node 20 and 22 against
  Convex `1.43.0` and the current npm `latest` release.

After that matrix passes, the repository is ready to version and publish
`0.1.0-rc.1` to the npm `next` tag. Publication, npm tag changes, and the final
`0.1.0` release require separate maintainer approval.
